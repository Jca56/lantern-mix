# 05 — UI

Two crates: `lmx_gpu` (puts pixels on screen) and `lmx_ui` (decides which pixels).
`lmx_app` composes screens from them inside a winit event loop.

## Accessibility is the design brief

Alva has poor eyesight. This is the first constraint on every screen, not a theme
option. Numbers below are **minimums in logical pixels**; the theme's scale factor
multiplies them and defaults to 1.0 on a laptop panel, and can be raised in settings.

| Element | Size |
|---|---|
| Body text (table rows, labels, menus) | **25 px** |
| Secondary labels (units, hints) | 20 px — the floor, anywhere |
| Deck readouts: BPM, time, key | 45 px, bold |
| Title | 60 px |
| Button height / any hit target | 55 / 50 px |
| Knob radius | 45 px (60 px for master) |
| Fader grip | 30 px |
| Waveform height (2-deck view) | ≥ 160 px each |
| Row height in the library table | 50 px |
| Borders / lines | 5 px |
| Gap / padding | 10 / 15 px |

**Every size is a multiple of 5** (45, not 44; 55, not 56) — Alva's rule, applied to
theme values and layout dimensions alike.

Rules: de-emphasize with color, never with size. No text smaller than 20 px anywhere,
ever. Whatever size instinct suggests, go up a step. Prefer fewer, well-spaced
controls; the hardware has the knobs, the screen shows *state*. **No glows, ever**
(Alva dislikes them; the radial-fade look also reads as a hard-edged disc after sRGB
encoding). **No help text / hint lines** in the UI. **No live-updating debug numbers**
(a frame counter at 240 Hz is just flicker).

**Palette direction (Alva, first review): warm, not blue, high contrast.** Dark warm
background, warm off-white text, amber accent, warm-leaning deck colors (orange, rose,
lime, violet). Each deck's color is used consistently for its waveform outline,
header, hot-cue markers and its channel on the controller LEDs. Alva keeps tuning
this on screen; `lmx_ui::theme` is the single place it lives.

## Screens

### Performance (Rekordbox-style, horizontal)

```
 ┌──────────────────────────────────────────────────────────────────────────────┐
 │ DECK 1  Title — Artist        BPM 140.00  KEY 8A   −02:14.5   [SYNC] [KEYLK]  │ header
 │ ▐▌▐▌▐▌▐▌  scrolling waveform, playhead fixed at center, beat ticks, cues      │ ≥160 px
 │ ▐▌▐▌  DECK 2 scrolling waveform                                               │
 │ DECK 2  Title — Artist        BPM 140.00  KEY 9A   −04:01.2   [SYNC] [KEYLK]  │
 ├──────────────────────────────────────────────────────────────────────────────┤
 │ overview 1 ▁▂▃▅▆▇▆▅▃▂▁▂▃▅▇▇▅▃▁    hot cues A B C D E F G H   loop  phase ●●●○  │
 │ overview 2 ▁▂▃▅▆▇▆▅▃▂▁▂▃▅▇▇▅▃▁    hot cues A B C D E F G H   loop  phase ●○○○  │
 ├──────────────────────────────────────────────────────────────────────────────┤
 │ tree: Collection / Playlists / Tags / Folders │ search ▭▭▭▭▭▭  BPM± KEY☑       │
 │                                              │ table: virtualized rows, 52 px │
 │                                              │ … (preview waveform per row)   │
 └──────────────────────────────────────────────────────────────────────────────┘
```

- Two decks by default; **4-deck view** stacks four shorter waveforms (decks 3/4 are
  what the GRV6's deck toggles switch to). The layout is a single function of window
  size and deck count.
- The playhead is fixed; the waveform scrolls. Zoom (beats visible) is a setting and a
  gesture (wheel over the waveform). Beat ticks, bar ticks, hot cues, memory cues,
  loop region, and the *other* deck's beat markers (for phase alignment) are drawn on
  the waveform.
- Level meters live next to each deck header (the hardware has the mixer; the screen
  shows levels and the master/limiter state only).
- FX panel: current effect, beat length, on/off, target — shown as a strip between
  waveforms and overviews when FX is touched, auto-hides otherwise.

### Library / prep

The same browser, full height, plus an **editor** for the selected track: big waveform
with zoom, grid editor (drag anchor, tap tempo, type BPM, ×2 / ÷2, lock), cue editor
(set/rename/color/delete, drag markers), loop editor, metadata fields, tags.
Keyboard-first for prep work: arrows move, Enter loads to preview deck, letters set
hot cues, space plays the preview deck through the cue bus.

### Settings

Audio device/profile/buffer size, controller profile + mapping editor, library roots,
analysis ranges (BPM min/max preset), key notation (Camelot / Open Key / musical),
scale factor, tempo fader range, crossfader curve.

## `lmx_ui` — the immediate-mode kit

```rust
let mut ui = Ui::begin(&input, dt, &theme, window_size);
ui.deck_header(&deck1_view);              // draws, and returns clicks as an enum
if ui.button(rect, "SYNC").clicked() { cmds.push(EngineCommand::Sync{..}) }
ui.waveform(rect, &wave1, view1);
ui.end(&mut painter);                     // emits the draw list
```

- **Identity**: widgets are identified by a hash of the *call site* (`#[track_caller]`
  `Location`) combined with the current id-scope; `ui.scope(id, |ui| …)` for widgets in
  loops (deck index, table row). No manual ids in normal code.
- **State**: a small map `Id → WidgetMemory` (scroll offset, drag origin, text cursor,
  open/closed). Hot / active / focused ids tracked like Dear ImGui.
- **Input**: pointer position/buttons/wheel, keyboard with modifiers and text input
  (from winit), file drops, and MIDI-originated "virtual" input where useful (browse
  encoder scrolls the focused list).
- **Layout**: `Rect` with cut/split/inset/grid helpers, `Row`/`Col` builders with
  gaps, everything in logical px, scale applied at the painter. Layouts are derived
  from shared rects, never from magic coordinates.
- **Widgets**: label, readout (big number), button, toggle, pad (with color state),
  knob, hfader/vfader, crossfader, meter (peak + RMS core + hold), text field (search,
  rename; IME-less, with selection), dropdown, tabs, modal, scroll area, **virtualized
  list/table** (only visible rows are built; sortable headers; drag-reorder),
  **tree**, **waveform** (scrolling + zoom + markers, GPU-backed), **overview** (with
  click-to-seek and played-region shading), **jog ring** (shows platter angle from the
  engine snapshot — visual only), beat-phase dots, key badge (color by Camelot).
- **Repaint policy** (laptop battery): `Continuous` while any deck is playing, a drag
  or scratch is active, or an animation is running; otherwise `OnEvent` — the loop
  sleeps in `winit`'s `Wait` mode until input, a MIDI event, a worker result, or a 1 Hz
  heartbeat (clock/readouts). At idle the app draws nothing and the GPU idles.

## `lmx_gpu` — the painter

- wgpu 28, surface from winit via `raw-window-handle` 0.6, sRGB swapchain, VSync
  (`Fifo`) by default. Resize-safe (skip frames while size is 0 or during reconfigure).
- **Shapes**: one instanced pipeline; each instance = `{rect, kind, radius, stroke,
  color0, color1, gradient dir, clip rect, layer}` with an SDF fragment shader for
  rect / rounded rect / circle / line / arc / ring. Everything the UI draws that is
  not text or waveform is this one draw call per layer.
- **Textures**: RGBA8 images (album art, icons) drawn as quads.
- **Waveform pipeline**: the analysis summary is uploaded as two textures per track
  (`peak/rms` RG8 and `low/mid/high` RGB8, one texel per column, fine + overview
  variants). A dedicated shader draws a waveform rect given `(first_column,
  columns_per_px, height, colors)`; scrolling and zooming are just uniform changes.
  Per-frame CPU cost for four waveforms: four instances.
- **Text**: `lntrn-text` (`TextRenderer::from_wgpu(device, queue, format, false)`);
  `queue(text, size, x, y, color, max_w, w, h)` per string, `render_layer` after the
  shapes of the same layer so overlays and modals stack correctly. Clip rects are
  pushed to both the painter and the text renderer together.
- **Layers**: 0 = base UI, 1 = overlays (dropdowns, drag ghosts), 2 = modals. Shapes
  then text, per layer, in order.
- **Scale**: the painter receives logical px and the window scale factor; text is
  rasterized at physical size so it is crisp under fractional scaling on Wayland.

## Testing

`lmx_ui` is testable headlessly: feed synthetic input over a few frames and assert on
the draw list and widget memory (a click lands, a drag scrolls, the table only builds
visible rows). `lmx_gpu` is exercised by Alva at the machine; no screenshots.
